# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — start Vite dev server with HMR
- `npm run build` — type-check (`tsc -b`) then produce a production build
- `npm run lint` — run ESLint over the repo
- `npm run preview` — serve the built `dist/` locally

There is no test runner configured.

## Architecture

A first-person archery game. The player is stationary at a fairground booth; gameplay loop is aim → draw → release → arrow physics → either stick in the ground or hit one of three rows of horizontally-sliding bullseye targets, which scores points and triggers an explosion + spinning-reload effect. The arrow is consumed on a target hit; misses still stick in the ground.

**Mount boundary.** `src/App.tsx` is a thin React shell that owns a container `div`, a click-to-play overlay, a game-over overlay, a `score` HUD, and a `TIME LEFT:` countdown HUD in the top-left. Inside a single `useEffect`, it constructs `new Game(container, setLocked, setScore, setGameOver, setTimeLeft)` and returns `() => game.dispose()`. **All Three.js lives behind the `Game` class** — no `useFrame`-style React-Three-Fiber, no Three objects in React state. The click-to-play overlay is shown/hidden by a `locked` boolean that `Game` pushes through `setLocked` when pointer-lock state changes; total score is pushed through `setScore` after each target hit; remaining seconds are pushed through `setTimeLeft` only when the displayed integer changes (so React re-renders at most once per second, not per frame); `setGameOver(true)` is pushed when **either** every target has reached `disabled` **or** the timer hits 0, swapping in a game-over card that displays the final score and a "New Game" button. The button calls `game.restart()` (which rebuilds the current level, clears arrows and effects, resets score **and the timer**, and pushes `setGameOver(false)`); the click-to-play overlay then reappears so the user can re-enter pointer lock. While `gameOver` is true, the container's click handler no-ops instead of requesting pointer lock and the crosshair is hidden.

**Round timer** (`Game.ts`). `ROUND_DURATION` (seconds) seeds `timeLeft`; the animate loop decrements it by `dt` **only while `this.locked` is true**, so the countdown freezes on the start screen, during the game-over card, and any time the player taps Esc — and resumes from that exact value when they click back in. The seconds emitted to React are `Math.ceil(timeLeft)`, tracked via `lastEmittedTime` so the callback fires only on whole-second transitions. Game-over cleanup is centralized in `triggerGameOver()` (cancels any draw, exits pointer lock, pushes the flag) and is called from both the all-disabled check and the timer-zero check; don't duplicate that cleanup if you add another end condition.

**World vs Level.** The scene is split into a shared, static `World` and a swappable `Level`:
- `World` (`src/game/World.ts`) is built once per `Game` and never rebuilt: the `Sky` (gradient dome + a PMREM environment map baked from the same gradient, assigned to `scene.environment` — this IBL is what lights the booth interior where the sun can't reach), fog matched to the sky's horizon color (set directly on the `Scene`, which is why its constructor takes the scene — and the renderer, for PMREM — and adds its own `.group`), a weak hemisphere fill and a warm low sun whose 2048² shadow frustum is fit tightly around the booth (`SHADOW_EXTENT`), the grass ground and its `CanvasTexture`, the `Booth`, and the scenery classes (`Barrels`, `CornerBows`, `Flowers`, `FrontRailing`, `KitScenery`, `Plants`, `Trees`). Each scenery class follows the same pattern: it exposes a `.group: THREE.Group` that `World` adds to its group, owns its own geometries/materials/textures (often shared across instances), and has a `.dispose()` that `World.dispose()` calls. Use this pattern when adding more scenery, and register it in `World`, not `Game`.
- `Level` (`src/game/Level.ts`) holds everything that differs per level: the `Target`s, the `TargetRow`s (with their bars), and the `RowFlags` multiplier pennants, all under a single `level.group`. It is built from a `LevelConfig` (`src/game/levels/LevelConfig.ts`) — pure data: `rows` (per-row z/y/tier/speed/direction/startCenterX), `targetsPerRow`, `targetSpacing`, `edgePadding`. Configs live one-per-file (`levels/level1.ts`) and are listed in order in `LEVELS` (`levels/index.ts`); add a level by authoring a config and appending it there. `Level` exposes `update(dt)` (rows slide, then targets tick), `findHit(from, to)` (earliest target hit, with its segment `t`), `isComplete` (all targets disabled), and `dispose()`.
- `Game.loadLevel(index)` clears all arrows and effects, removes + disposes the current `Level`, and builds `LEVELS[index]`. `restart()` uses it to rebuild the current level from scratch (which also resets row positions) rather than resetting targets in place. There is no level-progression UI yet — `loadLevel` is the hook for it. `ROUND_DURATION` is global, not per level.

**Game loop and ownership.** `Game` (`src/game/Game.ts`) owns the `WebGLRenderer`, `Scene`, `PerspectiveCamera`, the `Bow` viewmodel, the `World`, the current `Level` (+ `levelIndex`), an `Arrow[]`, and a transient `HitEffect[]`. Its `animate` method is a `requestAnimationFrame` loop that computes `dt` (clamped to 50 ms to survive tab-throttle) and runs steps **in this order**: advance the draw timer → `level.update(dt)` (each `TargetRow` slides positions, then each `Target` drives its cooling/reload state machine) → `arrow.update(dt)` + `resolveArrowCollisions` for each live arrow (any arrow that scored is removed from the scene and the array) → step every `HitEffect` and drop expired ones → render. Targets must move *before* arrows are tested so collisions use this frame's positions. The bow is added as a **child of the camera** so it tracks aim automatically — there is no separate viewmodel matrix.

**Rendering pipeline** (`src/game/PostFX.ts`). `Game.animate` calls `postfx.render()`, never `renderer.render` directly. `PostFX` owns an `EffectComposer` over a 4× MSAA half-float target (so the renderer is created with `antialias: false`): `RenderPass` → `GTAOPass` (ambient occlusion, run at `AO_RESOLUTION_SCALE` = half res via the `ScaledGTAOPass` subclass — full-res GTAO at DPR 2 cost ~75% of frame time) — that subclass also hides every `Sprite` during the AO pass, because GTAO's normal-override render skips points/lines but not sprites, which turned `HitEffect`'s score text into black boxes; any new non-mesh overlay should be excluded the same way → `UnrealBloomPass` → `OutputPass` (applies the renderer's ACES tone mapping + sRGB) → a custom grade `ShaderPass` (saturation, contrast, lift/gain, vignette). Because the scene renders into a linear HDR target, lit surfaces can exceed 1.0: keep `BLOOM_THRESHOLD` well above lit-surface levels (spotlit white target bands hit ~1–2) so only emissives like the booth bulbs bloom. Custom `ShaderMaterial`s should end with `#include <tonemapping_fragment>` / `<colorspace_fragment>` like `Sky` does. `PostFX.dispose()` disposes every pass then the composer; `Game.onResize` must call `postfx.setSize`.

**Materials and textures** (`src/game/materials.ts`). Shared look helpers:
- `addRimLight(mat, strength?)` patches a `MeshStandardMaterial` via `onBeforeCompile` (with a `customProgramCacheKey`) to add a fresnel rim to emissive. It's **opt-in** for rounded objects (tree foliage/trunks, barrel bodies, target tier rings, bow) — don't apply it to large flat surfaces like the ground, where grazing angles make the whole surface glow. Note it overwrites any existing `onBeforeCompile`.
- `createWoodTexture()` / `createFabricTexture()` are near-white canvas tint masks (the material's `color` supplies the hue), so one texture serves both `WOOD` and `DARK_WOOD`, or both red and white stripes. `createGrassTexture(metersPerTile)` is fully colored.
- Texture repeats assume **UVs in world meters**: call `setWorldUVs(geo)` on any geometry that uses these textures. It box-projects from local positions + normals, so it works on `BoxGeometry`, `RoundedBoxGeometry` (whose `parameters` are a 1×1×1 box — don't derive UVs from them), `ExtrudeGeometry`, and planes; it assumes the mesh is unscaled. Without it, default 0..1 UVs stretch one tile across each face.
- **Soft edges.** Booth posts and the counter top use `RoundedBoxGeometry` (`POST_BEVEL`, `COUNTER_BEVEL`); the counter top overhangs the front panel by `COUNTER_LIP` toward the player (Y is unchanged, so the bow/counter clearance invariant still holds). Valance stripes are beveled `ExtrudeGeometry` with a half-round scallop bottom; bunting ropes are thin `TubeGeometry` meshes (not `THREE.Line`, which renders as aliased 1 px hairlines and is skipped by AO); target backings are a rounded-rim `LatheGeometry`. Prefer these over raw boxes/cylinders for anything near the camera. `Booth` owns and disposes its wood/fabric textures explicitly because `material.dispose()` doesn't free maps.

**Third-party models** (`src/game/KitScenery.ts`, `public/models/`). Booth-side props (bucket of arrows on the counter, crates, sack, produce crates, wheelbarrow, weapon rack) come from the CC0 **KayKit Medieval Hexagon** pack, bundled into one `public/models/kaykit_props.glb` (~100 KB): each model is a top-level node named after its source file (base at y = 0, front facing +Z), all sharing one material and a 16 KB palette atlas. `KitScenery` loads it with `GLTFLoader` **asynchronously** — its group is empty until load — and places `clone()`s from the `PLACEMENTS` table (clones share geometry/material, so disposal walks the loaded library once, not the clones). If `dispose()` runs before the load resolves (StrictMode double-mount), the late result is disposed on arrival. Omitting `rotY` turns a model to face the player. The surroundings are deliberately kept simple — a forest clearing of the procedural `Trees` — rather than a kit-built village; a village/castle/clouds pass was tried and removed. Placements around the booth must avoid the sight-lines blocked by the booth walls (anything roughly behind `x = ±HALF_WIDTH` past `FRONT_Z` is invisible). To change the bundle: source zips live in git-ignored `temp/`; extract them outside the repo, then run `tools/pack_kaykit.py` headless (`/Applications/Blender.app/Contents/MacOS/Blender -b --factory-startup --python tools/pack_kaykit.py -- <gltf_root> public/models/kaykit_props.glb <contact_sheet.png> <rel/path1,rel/path2,...>`). It merges the duplicated atlas/material, prints per-model sizes, renders a labeled contact sheet for previewing, and exports the GLB. Pass the **full** model list each time — it rebuilds the bundle from scratch.

**Input.** Pointer Lock API on the renderer canvas. Mouse-look uses a `THREE.Euler` in `'YXZ'` order so yaw and pitch don't fight each other; pitch is clamped to ±(π/2 − ε). Spacebar drives a one-shot draw state (`drawing`, `drawTime`, `spaceHeld`); losing pointer lock cancels any in-progress draw so the bow doesn't get stuck mid-pull.

**Bow viewmodel coordinate convention** (`src/game/Bow.ts`). The bow's local frame matches the camera's: bow-local `−Z` points away from the archer (toward the target), `+Z` points back at the archer. Limbs curve toward `−Z` (back of bow faces target); the string's three-point polyline sits at `+Z` and the middle vertex slides further `+Z` as draw increases. The nocked arrow is a child of the bow group and inherits this same convention. If you change the bow's parent transform, preserve this orientation or `setDraw` will pull the string the wrong direction.

**Firing geometry — important.** Arrows are **not** spawned from the bow's tip. Direction is `camera.getWorldDirection()` (so the crosshair is the source of truth), and the origin is the camera position offset forward + right + down to *appear* to leave the bow. This keeps aim accurate; if you make the spawn truly bow-relative, expect arrows to miss the crosshair at close range.

**Arrow physics** (`src/game/Arrow.ts`). Each arrow integrates its own velocity with `GRAVITY = 22 m/s²` (semi-implicit Euler) and snapshots `prevPosition` at the top of `update(dt)` so callers can use `[prevPosition, object.position]` as the segment for collision tests. The mesh is built so its local `−Z` is the tip, which lets `lookAt(position + velocity)` re-orient the arrow along its trajectory each frame. `Arrow` exposes only `stickToGround()` — target hits are handled by `Game` removing the arrow outright (see *Arrow consumption* below). Ground collision is the half-space `y ≤ 0`: on contact, the arrow snaps to `y = 0`, advances 6 cm along travel direction to embed the tip, and sets `stuck = true` to skip further updates. There is currently **no broadphase, no scene collision (booth walls are decorative), and no arrow lifetime cap** — ground-stuck arrows accumulate in `Game.arrows` forever.

**Hit detection** (`src/game/Target.ts`). `Target.testHit(from, to)` converts the segment into the target's local frame and intersects the disk plane (local `z = 0`). Only crossings from `+Z` (front face, the side facing the player) toward `−Z` register, so shots from behind never score. `Game.resolveArrowCollisions` asks `level.findHit` for the earliest segment-`t` across all targets, then compares against the ground-plane `t` so a target hit always wins when both happen in the same frame. Rely on Three r184's `worldToLocal`/`localToWorld` calling `updateWorldMatrix` internally — moving targets are tested against this frame's positions even though the renderer hasn't run yet, so we don't need explicit `updateMatrixWorld` calls after `row.update`.

**Targets, rows, and tiers.** `Target` is split into a `bullseye` group (wood backing + colored scoring bands) and a persistent tier `ring` (a torus that lives **outside** the bullseye group so it survives explosions). A small state machine — `idle | cooling | reloading | disabled` — drives the hit response: `onHit()` hides the bullseye, increments `hitCount`, and starts cooling; after `COOLING_TIME` the bullseye reappears and ease-outs from scale 0.1 → 1 while spinning `RELOAD_SPIN_TURNS` revolutions around its normal axis over `RELOAD_TIME`. **Important:** the cooling→reloading transition must set the initial reload pose (`scale = 0.1`, `rotation.z = 0`) *before* flipping `bullseye.visible = true`, otherwise the mesh renders one frame at its previous full-size pose and flashes. After `MAX_HITS` hits the target enters `disabled` instead of reloading: bullseye stays hidden permanently and the ring's `color`+`emissive` flip to `TIER_DARK_COLOR[tier]` so the player can read which slots are dead. While not idle, `testHit` returns `null`. Final score = band score × tier multiplier; `testHit` returns the multiplier alongside the score so `HitEffect` can render an "Nx" sprite above the score readout for any tier with multiplier > 1. Tier (`green | blue | purple`) maps to multipliers `1 | 2 | 3` and to the ring's color. `TargetRow` (`TargetRow.ts`) groups three targets at fixed X-offsets, slides the row's center along X within bounds, and bounces at the walls. Adjacent rows in each `LevelConfig.rows` are configured with opposite `direction` values so motion alternates row-to-row. `TargetRow` also owns a `barsGroup` of `targets.length + 1` cylinder segments (color `TIER_DARK_COLOR[tier]`) that visually connect adjacent target rings to each other and to the side walls — `applyPositions` rebuilds endpoint pairs from the row's `centerX` plus `TARGET_RING_OUTER` so inter-target segments translate rigidly with the row while the two outer (wall ↔ outermost-target) segments stretch each frame via `mesh.scale.x`. `Level.buildTargetRows` adds each `row.barsGroup` to the level group and `row.dispose()` releases the shared geometry/material. `Target.ts` exports `TIER_COLOR`, `TIER_DARK_COLOR`, and `TIER_MULTIPLIER` so other modules (`RowFlags`, `TargetRow`) can stay in sync with the tier palette.

**Hit effects** (`src/game/HitEffect.ts`). Spawned by `Game` at the world-space hit point when a target is destroyed, ~1 s lifetime. The effect is **world-space, not parented to the moving target**, so debris and the `+score` text stay where the hit happened while the row continues to slide. ~36 debris particles share one `BoxGeometry` (single `dispose()`) but each has its own `MeshStandardMaterial` so opacity fades independently. The score readout is a `THREE.Sprite` with a `CanvasTexture`; `SpriteMaterial.map` is **not** auto-disposed by `material.dispose()`, so `HitEffect.dispose()` walks its materials and calls `.map?.dispose()` itself — apply this same pattern when adding sprite-based UI.

**Arrow consumption vs ground stick.** A target hit removes the arrow entirely: `Game.animate` collects consumed arrows during the iteration, then after the loop `scene.remove`s and `dispose`s each one and filters them out of `this.arrows`. A ground hit calls `arrow.stickToGround()` and leaves the arrow in the array forever. If you add a third collision class (e.g. solid walls), follow the *consumed* path so arrows aren't double-counted as stuck.

**Booth coordinates and counter clearance** (`src/game/Booth.ts`). The player stands at world `(0, EYE_HEIGHT, 0)` looking down `−Z`; the booth opens toward the player. `Booth.ts` exports `HALF_WIDTH`, `FRONT_Z`, `BACK_Z`, and `ROOF_Y` so `Level` can compute target movement bounds against the booth interior. **Non-obvious invariant:** `COUNTER_TOP_Y` (≈0.95) sits just below the bow viewmodel's lower-limb tip in world space (≈0.97 when looking forward). Raising the counter, lowering the bow's `group.position.y`, or increasing `BOW_HALF_HEIGHT` will clip the bow into the counter — adjust both together.

**Tunables** live as module-level constants at the top of each file: `MAX_DRAW_TIME`, `MIN_ARROW_SPEED`, `MAX_ARROW_SPEED`, `MOUSE_SENSITIVITY`, `EYE_HEIGHT`, `ROUND_DURATION`, `EXPOSURE` in `Game.ts`; sun/shadow/env constants in `World.ts`; sky palette in `Sky.ts`; `RIM_STRENGTH`/`RIM_POWER` in `materials.ts`; AO/bloom/grade constants in `PostFX.ts`; per-level row layout, speeds, and target spacing in `src/game/levels/*.ts`; `STRING_REST_OFFSET`, `STRING_MAX_DRAW`, `BOW_HALF_HEIGHT` in `Bow.ts`; `GRAVITY`, `SHAFT_LENGTH` in `Arrow.ts`; `TARGET_RADIUS`, `BANDS` (radii + scores), `TIER_MULTIPLIER`, `COOLING_TIME`, `RELOAD_TIME`, `RELOAD_SPIN_TURNS` in `Target.ts`; `PARTICLE_COUNT`, `DURATION` in `HitEffect.ts`; the booth dimension constants (`HALF_WIDTH`, `FRONT_Z`, `BACK_Z`, `ROOF_Y`, `COUNTER_TOP_Y`) in `Booth.ts` — the first four are exported because `Level` clamps target bounds against them.

**Disposal contract.** Because of React 19 StrictMode (see below), `Game.dispose()` must be exhaustive: cancel the RAF, remove every `window`/`document` listener it added, exit pointer lock if held, dispose every per-class object that owns Three resources (`Bow`, `Level` → its targets/rows/flags, `World` → sky dome + env map/booth/scenery/ground + grass `CanvasTexture`, `PostFX` → passes + composer render targets, every active `HitEffect`, every `Arrow`), then `scene.traverse` to dispose anything else reachable, call `renderer.dispose()`, and remove the canvas from its parent. Each class exposes its own `dispose()` for symmetry. **Two non-obvious points:** (1) `SpriteMaterial.map` and any other texture on a material must be disposed explicitly — `HitEffect.dispose()` does this; (2) when many objects share one geometry (e.g. `HitEffect`'s particle box), track the geometry on the owning class and dispose it once, not once per mesh. When adding new long-lived Three resources, wire them into this teardown path — into `World.dispose()` for shared scenery or `Level.dispose()` for per-level content (which also runs on every `loadLevel`, so leaks there compound on each restart).

## Stack notes that affect how code is written

- **React 19** with `StrictMode` enabled in `src/main.tsx` — effects and refs may run twice in dev; Three.js setup that mounts to a DOM node must clean up renderers, geometries, and event listeners in the effect's cleanup function or it will leak on every re-mount.
- **TypeScript config is strict in non-obvious ways** (`tsconfig.app.json`):
  - `verbatimModuleSyntax: true` — type-only imports must use `import type { ... }`.
  - `erasableSyntaxOnly: true` — no enums, namespaces, or parameter properties; use `const` objects + union types instead.
  - `noUnusedLocals` / `noUnusedParameters` — unused identifiers fail the build, not just lint. Prefix with `_` to silence intentionally.
- **Vite** is the only bundler; static assets go in `public/` (served at `/`) and are referenced by absolute path.
